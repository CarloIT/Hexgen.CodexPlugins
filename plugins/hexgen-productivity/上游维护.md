# Grill Me 来源与维护

本插件提供两个独立入口：`grill-me-single` 显示为 **Grill Me Single**，`grill-me` 显示为 **Grill Me**。二者保留原入口的显式调用策略，避免普通任务自动进入追问。它们属于通用工作方式，可用于软件设计和非代码场景。

## 固定的单问题版本

[Grill Me Single](skills/grill-me-single/SKILL.md) 来自用户本地 `grill-me` 入口所引用的 `grilling` 正文。迁入时只合并入口、改技能标识和说明，保留英文正文及逐题等待的行为。原始两个文件的路径与 SHA-256 已记录在[上游来源](上游来源.json)中；本地安装所对应的历史上游 commit 未获确认，不将它冒充为当前上游版本。

Single 不引用上游版的规则。更新上游时不改它；若以后明确修改 Single，须独立说明行为变化、更新其校验值并验证一次只问一个问题。

## 跟踪上游的版本

来源：[mattpocock/skills](https://github.com/mattpocock/skills)。采用的完整 commit、跟踪目录、上游文件与本地文件映射、SHA-256 及 Git blob SHA-1 均保存在[上游来源](上游来源.json)。[MIT 许可证](LICENSE)保留上游版权与完整许可文本。

- [入口快照](上游快照/入口.md)：逐字节保留上游 `skills/productivity/grill-me/SKILL.md`，用于审查和更新比较。
- [规则快照](skills/grill-me/references/上游追问规则.md)：逐字节保留上游 `skills/productivity/grilling/SKILL.md`，运行时由插件入口读取。
- [Codex 入口](skills/grill-me/SKILL.md)：用相对文件读取替代上游 `Skill` 工具调用，不按名称寻找个人目录或其它插件中的 `grilling`。子 Agent 不可用时允许自行查证，这是明确的兼容适配。显示名称和技能标识保持 Grill Me / `grill-me`。
- 将上游 `disable-model-invocation: true` 的入口意图映射为两个入口各自 `agents/openai.yaml` 中的 `allow_implicit_invocation: false`，不依赖客户端识别上游专用字段。

快照使用普通 Markdown 文件名，避免被发现为第三个技能。上游更新不保证一直保留当前的分轮多问题行为；跟踪原版意味着审查其未来变化，不应把旧的行为描述固定成更新后的事实。减少轮次也不保证减少 token。

## 检查与采纳更新

在仓库根目录的 PowerShell 中执行，需要 Python 3.9+，只使用标准库：

```powershell
python '.\scripts\检查上游技能.py'
python '.\scripts\检查上游技能.py' --offline
python '.\scripts\检查上游技能.py' --json
```

默认先验证本地快照与 Single 完整性，再解析上游 `main` 的 commit，并检查该固定 commit 下两个技能目录的全部文件及根 LICENSE。新增依赖文件、文件删除、内容变化或许可变化都会报告；上游其它目录的提交不会被误报为技能更新。`--ref <分支、标签或完整 commit>` 可检查指定版本，不会改变采用记录。

退出码：`0` 表示检查成功且无相关更新（离线模式仅表示本地完整性通过），`2` 表示有更新，`1` 表示错误。网络、TLS、GitHub 限流、文件树截断或本地快照损坏均报错，不会当成“已是最新”。脚本没有写入、安装、提交或发布功能。

采纳更新时：

1. 查看报告中的文件变化和 GitHub 比较链接，审核完整技能目录及新增引用；遇到依赖指向目录外时将它纳入来源记录与检查范围，或明确决定如何适配。
2. 固定新的完整 commit，从该 commit 读取需要的原文与许可证；更新文件映射、校验值和最少量 Codex 适配。不要将任意 GitHub 内容直接执行为维护命令。
3. 独立保留 Single；运行离线完整性检查、仓库结构校验和 `git diff --check`。按需运行[检查脚本验证](../../scripts/验证上游检查.py)。
4. 在隔离配置中验证安装和技能发现，实际试用代表性请求，检查分轮依赖、事实查证及授权边界；Single 仍逐题问答。
5. 更新本插件版本和根 CHANGELOG；按作者授权提交与发布。团队更新插件后在新任务使用。

当前提供手动、可重复运行的检查能力，未创建定时检查或自动更新任务。需要定时跟踪时，可让调度器运行同一个只读脚本，仅在相关文件变化或检查失败时通知维护者；采纳和发布仍走上述验证流程。
