# 触发与输出示例

## 应触发

- “请根据当前代码和候选环境，写一份作者第一次操作也能照做的中文人工验收手册。”
- “这个修复只影响导入失败和异步取消，请更新手测步骤，并保留未受影响功能的已有通过证据。”
- “把评审结论整理成点击、观察和记录都明确的验收清单；不要替我签收。”
- 本 Skill 已生成手册后，作者继续回报“案例 A1 只做了提交，还没查终态，请登记”：沿用结果登记规则，保留部分执行证据，无需重写手册。

## 不应触发

- “为这些接口补 Playwright 和集成测试。”这是自动化测试实现。
- “修复点击保存后界面卡住的问题。”这是代码诊断或实现。
- 独立请求“我已完成验收，请把结果登记到发布计划”：这是计划维护；不自动触发手册编写。若同时要求更新已有手册，只处理相应部分。
- “审查这个测试计划有没有覆盖边界。”这是测试审查；只有要求产出作者操作手册时才使用本 Skill。

## 输出片段示例

以下产品行为、按钮名、字段和时间安排只属于虚构示例，用来展示粒度；实际成稿必须从目标产品核实操作现状，并从已确认的需求或契约确定通过标准，不能直接复用示例事实。

### 环境交接与候选变化：沿用现有控制台

虚构输入：上一阶段已交付隔离环境启动/停止脚本；候选 `queue-r4` 的正式控制台能提交和取消任务，专项工具只能模拟超时。当前修复了取消后的迟到写入，作者此前在 `queue-r3` 通过了名称校验；本次只要求更新手册。

输出应从现有脚本和控制台核实准备、就绪、版本与退出方式，正常提交/取消使用控制台，超时专项说明模拟替代的环节及恢复操作。不新建一套网页或宿主。把迟到写入、取消终态和相关副作用列为重验项；名称校验只有在核实代码路径、配置及风险前提未受影响后才能保留旧证据，并仍标明其原候选。没有作者本轮回报的案例保持未执行，AI 复核和自动测试另列。

若发现启动脚本尚未交付，或控制台只返回固定演示结果，则说明对应缺口和受影响案例，指向开发任务补齐最小入口；不捏造命令或将模拟成功记为真实链路通过。仅编写手册的任务继续完成可核实部分，不自行实现宿主或更改验收契约。

### 精简清单：空名称应被拒绝

**范围与前提：** 只验证候选 `form-r2` 的名称校验及有效保存。已确认需求规定空名称不得新增记录；当前候选有`名称`、`保存`、`刷新记录`和记录行内的`删除`控件。使用作者独占的隔离测试列表，点击`刷新记录`并记录条数 N。

| 做什么 | 看到什么 | 记录什么 |
|---|---|---|
| 清空`名称`，点击`保存`一次，再点击`刷新记录` | 显示“名称不能为空”，条数仍为 N | 提示原文及操作前后条数 |
| 在`名称`输入本次唯一名称，点击`保存`一次，再点击`刷新记录` | 显示“保存成功”，新增该名称且总数为 N+1 | 新记录名称、ID 及条数 |

**判定：** 两步必要证据齐全才通过；空名称被保存、有效名称不能保存或增量不符均为失败。版本不符等外部条件使目标行为无法判断时记受阻；仅做完第一步且无违约或阻断时记部分执行。

**恢复：** 记录证据后，仅对本次新增记录点击行内`删除`，在确认框核对名称并点击`确认删除`；刷新确认该记录消失、条数回到 N。保留失败证据，不清空其他记录。

**结果：** 未执行。填写实际状态、完成步骤、提示、前后条数、待补证据及恢复情况即可，不必再展开控件、日志或异步章节。

### 案例 A1：一次提交只新增一条记录

**基线：** 点击`刷新记录`，记下当前总数 N。

**前提与查询安排：** 使用作者独占的隔离环境。本示例需求规定任务完成后恰好新增一条记录，未规定完成期限；验收安排从显示任务 ID 起立即查询，此后每 2 秒查询一次，最多观察 60 秒。这是人工操作预算；查到终态、发现契约违背或遇到外部阻断即停止轮询，不据此承诺产品应在 60 秒内完成。

| 步骤 | 做什么 | 看到什么 | 记录什么 |
|---|---|---|---|
| A1-1 | 点击`新建任务`，填写有效名称后点击`提交`一次 | 页面提示“已接受”，并显示任务 ID | 完整任务 ID |
| A1-2 | 按上述查询安排点击`查看状态`；到停止条件即停止，不重复提交 | 检查是否显示“已完成”和完成时间；直接查到终态也有效 | 实际状态、完成时间或已观察时长；未完成时记录停止原因 |
| A1-3 | 确认任务完成后点击`刷新记录` | 总数变为 M，且 M-N=1 | M 和新增记录名称 |

**通过标准：** 任务进入成功终态，且记录恰好新增 1 条。

**失败标准：** 前提成立时任务进入非预期的失败终态，或完成后记录增量不为 1。若目标产品另有已确认的完成期限，只有取得期限违约证据后才能按该契约判失败。

**受阻标准：** 环境版本不符、外部网络中断，或有其他操作者插入记录导致增量无法归因，且尚无该案例违约证据。产品自身的状态查询故障是否为失败，须依据本次契约和验收目标判断。

**部分执行：** 作者只看到“已接受”就主动停止，或观察 60 秒仍无终态且无违约证据或外部阻断。记录已完成步骤、完整任务 ID、最后状态和待查终态，不判通过或失败；任务未结束前不清理其数据或重复提交。

**恢复：** 若任务仍在运行，先保留 ID 和现场，使用目标环境已核实的停止或取消入口处理；确认不会再写入后，才清理本次新增记录。正式手册须补齐真实入口、停止确认方式及恢复顺序，不能直接照抄本片段。

### 案例 A2：不支持的文件被正确拒绝

1. 点击`刷新记录`并记总数 N。
2. 点击`选择文件`，选择不受支持的文件，再点击`开始导入`一次。
3. 记录界面实际显示的错误码和 `ErrMsg`；再次刷新并记总数 M。

**通过标准：** 系统按当前契约拒绝导入，错误映射正确，且 M-N=0。这里“导入失败”正是负向案例通过。

**不要扩大结论：** 如果只核对了界面错误和记录增量，就不能顺带声称内部异常详情已返回、服务端日志已保存或发布验收已通过。
