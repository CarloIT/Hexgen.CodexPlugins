# 中文人工验收手册

交付一份第一次接触该功能的作者也能照做、照看、照记的 Markdown 手册。手册负责定义操作与判定，不替作者执行，不把自动化证据或推测写成人工结论。

## 工作流

1. **确定候选与范围**
   - 明确本次变更、候选标识、构建时间（适用时）、环境与配置，以及人工验收要覆盖的风险；给出作者可核对的版本入口或产物清单，使手册、实际运行入口和结果记录对应同一候选。日期或页面能打开本身不足以证明版本匹配。
   - 按本次必验、受影响回归及长时间运行/真实设备等专项组织范围，注明专项属于本阶段门槛还是计划已明确的后续工作，不自行延后必验项。选择最小充分回归；修复或更换候选后，列明重验项及理由，未受影响且候选链仍有效的已有通过证据可以保留，注明来源与适用条件。
   - AI 设计/代码复核、自动化通过、人工通过、真实设备验证和发布签收分别记录，不互相代签。

2. **分别核实操作现状与判定依据**
   - 只检查与本次验收有关的代码、界面、接口和配置。操作入口、控件名称及当前可观察行为依据实际实现核实；通过标准依据已确认的需求或契约，不能把当前缺陷写成正确预期。
   - 按案例需要核对真实按钮、菜单、字段、路由、状态值、超时、重试和环境启动/关闭方式，不因模板列有某项就扩大调查。
   - 复用项目已有候选、环境与入口，把准备/启动尽量写成一条已核实命令或少量操作，列出工作目录、前提、就绪表现、地址/入口和缺失依赖的识别与处理；已有运行环境可从版本及就绪核对开始，无需重建。区分源码核实与实际启动验证，未实跑如实说明。入口不存在或不可用时，列为交付缺口及受影响案例的前置依赖，不能编造路径交给作者调通。
   - 正式产品入口可用时，正常业务案例优先使用该入口。模拟设备、故障注入、种子数据和模拟时间等明确标出替代环节、启用/恢复方法及证据限制；模拟界面未调用实际后端时只验证已约定的原型目标，不据此声称产品链路或真实设备通过。
   - 涉及错误或日志时，分开确认：内部异常、对外状态或错误码、对外 `ErrMsg`、是否调用日志出口、日志是否实际持久化。没有证据就缩小结论或标记待确认。
   - 若需求、设计、代码、配置或界面互相矛盾，明确差异及其影响；保留已确认的契约标准，不编造实现已满足预期的结论。
   - 先查可发现的事实；只有仍缺失且影响判定、范围或授权的信息才向作者提问。继续完成已明确的案例，将待确认问题限定到相关案例；无法核实的点击路径或判定不写成可执行事实。

3. **把每个案例写成可执行证据链**
   - 每个案例都包含前提或基线，以及“做什么 / 看到什么 / 记录什么”。
   - 使用界面当前显示的真实控件名称；不要让作者把抽象动作翻译成点击路径。
   - 计数、列表、日志或副作用优先记录操作前基线 `N`，再比较本次增量；除非环境保证全新，不要求全局绝对值从零开始。
   - 必要时加入无副作用的只读查询。默认用短命令或单次查询说明，不为排版或少量重复操作编写脚本。

4. **正确表达负向与异步行为**
   - 负向测试中，系统按契约拒绝、报错、超时或取消可以是案例通过；“操作成功”和“测试通过”不是同一概念。
   - 异步操作至少区分“已接受”“运行中”“终态”。获得执行 ID 或接受响应只证明已接受，不能直接判定业务成功；快速完成不要求人为捕捉“运行中”。
   - 写明查询间隔、观察上限、计时起点和停止条件及其依据。产品规定的完成期限与人工观察时限分开说明；仅达到观察时限仍无终态，且无已确认违约或外部阻断时，记“部分执行”，保留已有证据和待查终态，不无限等待或直接判产品失败。
   - 若底层工作可能在超时或取消后继续，分别验证管理终态、迟到结果和副作用；不要把协作式取消写成强制终止。

5. **明确结论与恢复边界**
   - 使用“通过 / 失败 / 受阻 / 部分执行 / 未执行”五种状态，具体定义见模板的结果状态章节。已做部分步骤且尚不足以判定时，保留已完成步骤和缺失证据；已有明确违约或外部阻断时分别登记失败或受阻，不用“部分执行”掩盖。
   - 只登记作者明确报告的结果。部分步骤通过不扩大为整组、整阶段、真实设备或发布通过。
   - 写明与本次操作有关的正常退出、残留状态清理、环境恢复和证据保留方式，限定本次创建或占用的资源，不关闭共享宿主或清理无关数据。外部条件导致无法判断才记受阻；若启动或页面可用性就是验收目标，且其前提成立，违反契约应判失败。

## 成稿要求

- 新建手册时按变更复杂度选用 [人工验收手册模板](assets/人工验收手册模板.md) 中的内容：小改动用精简清单，复杂流程展开详细章节。保留前提、“做 / 看 / 记”、判定、必要恢复和结果登记；控件说明、日志、查询及异步章节按需使用，不要求固定章节数，不保留无意义占位符。
- 需要校准触发边界或案例粒度时，读取 [触发与输出示例](references/触发与输出示例.md)；示例中的产品和控件名仅演示写法，不是可复用事实。
- 本技能负责手册及结果登记，默认交付说明和 Markdown。环境、脚本及页面由项目开发任务按阶段计划实现；已有授权内的验收工具实现沿用该授权，单独请求编写手册不扩大为搭建环境。发现缺口时指出所需最小补充与受影响案例，交由相应开发任务落实；不因模板新增审批流、数据库或自动化基础设施。
- 命令若会启动或停止宿主、连接真实系统、改变数据或影响桌面，必须与只读查询分开说明，并遵守当前任务的授权边界。
- 长整型标识、哈希和执行 ID 按字符串原样记录，避免被表格软件改写。
- 完成前复核：候选、运行入口、手册及证据可对应，准备/退出清理可照做，模拟范围与候选变化后的重验安排明确；操作入口已核实，判定有已确认的需求或契约依据；每个案例都有“做 / 看 / 记”；涉及统计时采用增量；涉及异步时阶段含义和停止条件清楚；结果模板不预填通过；必要恢复可执行；范围没有被扩大。

## 结果登记

若作者随后回报本手册的结果，只登记其明确提供的状态和事实，并按五种状态定义归类。含糊描述保留原意并列出缺口；已完成的步骤不能抹成未执行，也不能替作者补做、推断未报告的结果或把最低验收证据升级为阶段完成。独立的发布计划维护不因此自动触发手册重写。
